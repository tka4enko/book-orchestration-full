## Обязательные правки (выполнить в первую очередь)
- `app/orchestrator_chat_agent.py:52`
  - **Что сделать:** создать отдельный клиент `router_llm = ChatOpenAI(..., temperature=0)` и использовать его только внутри `node_intent`; текущий `llm` с `temperature=0.7` оставить для генеративных ответов.
  - **Почему важно:** температурный шум в классификаторе приводит к случайным переключениям режимов и дополнительным вызовам узлов. Холодный клиент даёт воспроизводимый результат и сокращает холостые проходы графа.
- `app/orchestrator_chat_agent.py:203`, `app/orchestrator_chat_agent.py:249`, `app/orchestrator_chat_agent.py:548`
  - **Что сделать:** заменить синхронные вызовы `llm.invoke` на `await llm.ainvoke(...)` (или обернуть `invoke` в `asyncio.to_thread`).
  - **Почему важно:** сейчас вызов блокирует event loop; под нагрузкой весь граф «замерзает», а задержка складывается из времени каждого шага. Асинхронный вызов освобождает цикл и позволяет параллельно обрабатывать другие корутины и сессии.
- `app/orchestrator_chat_agent.py:33-36`
  - **Что сделать:** сменить типы полей `previous_criteria`, `seen_books` на списки (`List[str]`) либо приводить множества к списку перед сохранением в `MemorySaver`.
  - **Почему важно:** стандартный сериализатор `MemorySaver` пишет состояние в JSON; множества (`set`) не сериализуются и падают с `TypeError`, из-за чего сессия теряет память.
- `app/orchestrator_chat_agent.py` (нижняя часть)
  - **Что сделать:** восстановить/добавить экспорт `ensure_pydantic_state` (или убрать импорт в `tests/test_chat_agent_conversations.py`).
  - **Почему важно:** тесты и внешние вызовы ожидают этот хелпер; без него модуль не импортируется и падает при старте.

## Следующий этап (после критичных правок)
- `app/orchestrator_chat_agent.py:156-209`

  - **Почему важно:** сейчас функция каждый раз тянет полный каталог, и при росте базы время ответа в узле `clarify` растёт линейно. Кеш стабилизирует задержку и разгружает хранилище.

  - **Почему важно:** лишние вызовы LLM удорожают и замедляют поток. Сохранение и повторное использование уже известных предпочтений снижает задержку и стоимость.
- `tests/test_chat_agent_conversations.py:85-124`
  - **Что сделать:** привести моки к актуальному API — сверить ключи `recommendations`, `response`, метрики с боевыми функциями.

## Можно отложить
- Реализация семантического кэша для LLM и стриминга ответов (SSE/WebSocket).
  - **Почему позже:** требует инфраструктуры (кэш-хранилище, протокол потоковой отдачи) и не критична до стабилизации основного флоу.
- Rule-based шаблоны в `node_clarify` для простых уточнений без LLM.
  - **Почему позже:** даст экономию стоимости, но не влияет на стабильность прямо сейчас; можно вернуться, когда основные изменения обкатаются.
